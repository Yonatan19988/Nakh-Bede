# نخ بده

بازی حدس کلمات گروهی — نسخه‌ی وب، قابل نصب روی گوشی (PWA).

هر تیم به نوبت یک نفر را به‌عنوان توضیح‌دهنده می‌فرستد و بقیه حدس می‌زنند.
هر بار یک کلمه نمایش داده می‌شود و فقط توضیح‌دهنده آن را می‌بیند. امتیاز
خالص هر راند، همان تعداد خانه‌ای است که تیم جلو (یا عقب) می‌رود.

---

## ساختار پروژه

```
.
├── index.html                صفحه‌ی اصلی؛ فقط اسکلت و لینک‌ها
├── css/
│   └── styles.css            تمام استایل‌ها
├── js/
│   ├── data.js               محتوای بازی: فهرست کلمه‌ها، کارت‌های فرمان،
│   │                         افکت‌هایشان و مختصات خانه‌های نقشه
│   ├── app.js                کل منطق بازی و رابط کاربری
│   └── firebase.js           اتصال به Firebase (ماژول ES)
├── assets/                   تصویرها
│   ├── map-60h.webp              نقشه‌ی تخته: نوار عمودی ۲۱۶۰×۱۱۸۸۰ با ۶۰ خانه (بندرعباس، شیراز، اصفهان، رشت، برج آزادی)
│   ├── logo.webp             لوگوی «نخ بده» با پس‌زمینه‌ی شفاف
│   ├── card-back.webp
│   ├── card-word.webp
│   └── card-action.webp
├── icons/                    آیکون‌های PWA
├── manifest.webmanifest      تنظیمات نصب روی گوشی
├── sw.js                     سرویس‌ورکر (کار آفلاین)
├── database.rules.json       قوانین امنیتی Firebase
└── .gitignore
```

**ترتیب بارگذاری اسکریپت‌ها مهم است:** `data.js` باید قبل از `app.js`
بیاید، چون `app.js` به ثابت‌های داخلش (`WORD_LIST`، `ACTION_CARDS`،
`ACTION_EFFECTS`، `CELL_COORDS`) تکیه می‌کند. هر دو اسکریپت کلاسیک‌اند و
در دامنه‌ی سراسری اجرا می‌شوند؛ فقط `firebase.js` ماژول است.

## اجرای محلی

سرویس‌ورکر و ماژول‌ها با `file://` کار نمی‌کنند، پس باید از یک سرور ساده
استفاده کنی:

```bash
python3 -m http.server 8000
# بعد در مرورگر: http://localhost:8000
```

یا با Node:

```bash
npx serve .
```

## انتشار روی GitHub Pages

۱. کل محتوای پوشه را در ریشه‌ی مخزن بگذار (نه داخل یک زیرپوشه).
۲. در Settings ← Pages، شاخه و پوشه‌ی `/ (root)` را انتخاب کن.
۳. چند دقیقه بعد آدرس فعال می‌شود.

تمام مسیرها نسبی‌اند (`./` و `assets/...`)، پس اگر بازی در زیرپوشه هم سرو
شود درست کار می‌کند.

**بعد از هر انتشار:** سرویس‌ورکر نسخه‌ی قبلی را از کش می‌دهد و نسخه‌ی تازه
را در پس‌زمینه می‌گیرد؛ یعنی تغییرات در دفعه‌ی بعدی باز کردن دیده می‌شوند.
اگر خواستی به‌روزرسانی فوری باشد، عدد `CACHE` در `sw.js` را بالا ببر.

## Firebase

بازی آنلاین از Realtime Database و ورود ناشناس استفاده می‌کند. تنظیمات
اتصال داخل `js/firebase.js` است.

**قوانین فعلی (`database.rules.json`)** فقط کاربر واردشده را مجاز می‌کند و
فهرست‌کردن همه‌ی اتاق‌ها را می‌بندد، ولی روی فیلدها محدودیتی نمی‌گذارد —
یعنی هر قابلیت جدیدی بدون دردسر کار می‌کند.

برای انتشار قوانین: Firebase Console ← Realtime Database ← Rules ←
جای‌گذاری محتوای فایل ← Publish.

پیش‌نیازها در کنسول:
- Authentication ← Sign-in method ← Anonymous ← فعال
- Authentication ← Settings ← Authorized domains ← دامنه‌ی انتشار اضافه شود

## ذخیره‌سازی روی گوشی

بازی چند مقدار کوچک را در `localStorage` نگه می‌دارد (همه با پیشوند `nb_`؛
اگر مرورگر ذخیره‌سازی را ببندد، بازی بدون آن هم کار می‌کند):

| کلید | کاربرد |
|---|---|
| `game` | بازی تک‌گوشی نیمه‌کاره؛ در ابتدای هر نوبت ذخیره می‌شود و دکمه‌ی «ادامه‌ی بازی» را می‌سازد. با برنده شدن یک تیم پاک می‌شود. |
| `room` | آخرین اتاق آنلاین (کد، نام، تیم)؛ تا ۶ ساعت دکمه‌ی «بازگشت به اتاق» را نشان می‌دهد. با «خروج از اتاق» پاک می‌شود. |
| `name` | آخرین نامی که برای ورود به اتاق وارد شده |
| `seenTutorial` | اگر نادیده بماند، بنر آموزش و نقطه‌ی روی دکمه‌ی «آموزش» نمایش داده می‌شود |
| `installDismissed` | بنر نصب پس از نصب یا بستن دیگر نمایش داده نمی‌شود |
| `sound`، `haptic` | کلیدهای «صدا» و «لرزش» در تنظیمات |

لینک دعوت به شکل `آدرس-بازی/?room=ABCDE` است و برگه‌ی ورود با کد را با کد
پر‌شده باز می‌کند.

## کارهای باقی‌مانده

- بخش‌های سکه، فروشگاه، پروفایل، دوستان و کارت‌ها پشت فلگ
  `SHOW_FUTURE_FEATURES` در `app.js` خاموش‌اند
- نسخه‌ی دوزبانه (فارسی/عبری) جداگانه ساخته شده و در این پروژه نیست
- بازی از راه دور با صدا یا متن: ایده‌ها در [docs/remote-play-ideas.md](docs/remote-play-ideas.md) نگه داشته شده (فعلاً ساخته نمی‌شود)
